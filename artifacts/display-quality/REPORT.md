# 400×300 Japanese calendar display-quality result

1. **Font:** Noto Sans JP variable font, build-time subset rasterization.
2. **Weights:** dates remain existing Helvetica Bold bitmap; Japanese header/weekday metadata Medium; Rokuyō Regular; holiday labels Medium. Existing bold date/header hierarchy is unchanged.
3. **Rokuyō:** 13 px target raster, 1-bit, complex CJK glyph bounding boxes at least 11 px high.
4. **Holiday label:** 10 px Medium target raster, compact 8 px CJK advance (selected narrow glyphs 7 px) to retain full formal names.
5. **Glyph subset:** 262 UI + 57 holiday + 13 Rokuyō = 332 font entries, not a full CJK font.
6. **Generation:** Pillow draws Noto directly at each final target size into 1-bit BDF; bdfconv compiles const u8g2 arrays into firmware Flash. There is no runtime TTF parser or bitmap downscale.
7. **White rectangle root cause:** `u8g2_SetFont()` resets `font_decode.is_transparent` to 0 when the font changes. `DrawMonthDays()` previously selected Rokuyō/holiday fonts *after* setting transparent mode. Opaque glyph background spans then wrote GFX_WHITE, clearing both E-paper planes.
8. **Renderer changed:** Calendar text call sequence in `GUI/GUI.c`; shared u8g2 and framebuffer drawing algorithms remain unchanged.
9. **Transparency:** Final font is selected first, then transparent mode is enabled for Rokuyō and holiday labels. Glyph background pixels now leave both planes untouched. Today non-holiday Rokuyō is white on the red card.
10. **Holiday bar:** 2 physical pixels at `cellLeft + 1..2` in compact cells; today + holiday draws no separate bar.
11. **Measured glyph gap:** September 22 = 6 px; September 23 = 9 px, both greater than the 2–3 px minimum.
12. **Common anchor:** Both date and holiday label use `cell_center_x = cell_left + bw / 2`, with no bar-dependent x adjustment. Two-digit date glyph runs receive a 1 px optical correction independent of holiday state. For September 22 the anchor is x=144 and raster centers are 143.5/144; for September 23 the anchor is x=200 and raster centers are 199.5/199.5. The 0.5 px maximum visual-center discrepancy is one pixel-grid parity step.
13. **Changed files:** `GUI/GUI.c`, `GUI/fonts.c`, `tools/build_compact_font.py`, `tools/build_fonts.py`, font BDF renamed from `epd_jp_rokuyo_regular12.bdf` to `epd_jp_rokuyo_regular13.bdf`, `tests/render_jp_font_sheet.c`, `tests/calendar_display_quality.py`, `tests/test_header_render.py`, `tests/test_jp_font_subsets.py`, `tests/test_rokuyo_render.py`.
14. **Flash (text+data):** before 53,160 bytes; after 53,188 bytes; delta **+28 bytes**. nRF52811 build and link succeeded.
15. **RAM (data+bss):** before 1,776 bytes; after 1,776 bytes; delta **0 bytes**.
16. **Native preview:** `native-400x300.png` (2026-09-21 as today; Sep 26 is an ordinary cell).
17. **4× preview:** `nearest-4x.png` (nearest-neighbor only).
18. **Font preview:** `font-test-4x.png`, generated by compiling the same `GUI/fonts.c` and u8g2 renderer as firmware. It contains all six Rokuyō, specified header/holiday strings, complex glyphs, and digits.
19. **Holiday debug:** `holiday-layout-debug.png` from the firmware bitmap. Green lines: cell boundaries; blue line: shared center anchor; green boxes: date pixel bounds; cyan: label pixel bounds; orange: independent 2 px bar.
20. **Preview provenance:** `tests/render_calendar.c` calls the firmware `DrawGUI` and captures the actual black/red 1-bit framebuffer planes; `tests/render_jp_font_sheet.c` draws the compiled font arrays. PNG conversion changes only file encoding, and enlargement uses nearest-neighbor. No browser/system font or anti-aliasing is used for rendered glyphs.

Validation: font subset, reference layout, Rokuyō render, holiday geometry, 26 ordinary cell, Flash/RAM build, and rollback-copy hash checks passed. Physical display after this new build has not been tested or flashed.
